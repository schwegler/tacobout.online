# WordPress release updates

The theme uses the WordPress 6.1+ `Update URI` mechanism (theme minimum remains WordPress 6.4 / PHP 8.0). Its stable identity is `https://github.com/schwegler/tacobout.online`, and its directory remains **tacobout.online-main**. The header prevents WordPress.org name collisions; the hostname hook additionally requires the exact URI and directory. A renamed install is deliberately not updated.

Checks occur through core's update checks, not theme rendering. Public metadata is cached for an hour (network/JSON failures for 15 minutes). From 3.8.31, an administrator with theme-update permission using Dashboard → Updates → Check again clears both the theme metadata cache and core theme-update result before core checks again. Earlier 3.8.29/3.8.30 installations retain cached failures for up to 15 minutes; Check again does not clear their custom cache, so allow that TTL to expire after publishing the first release, then check again. A failed request after expiry can start another failure-cache interval; persistent non-discovery needs HTTP/filter diagnostics rather than repeated releases. No GitHub token, hosting credential, cookies or installed-theme inventory is sent. Requests have a five-second timeout, bounded redirects and response size, and use WordPress's safe HTTP API. Only an exact HTTPS package URL in this repository's matching numeric `vMAJOR.MINOR.PATCH` release is accepted. Same/older versions, malformed identity and incompatible WordPress/PHP requirements are ignored. No automatic-install settings are changed; administrators control installation through normal WordPress UI.

## Publish

After merge, create a stable GitHub Release whose tag matches `style.css`, for example `v3.8.29`. The release workflow runs all existing PHP, JavaScript, browser and packaging checks against the release commit before attaching `theme.zip`, `release.json` (SHA256 and per-file verification manifest) and `tacobout-update.json`. Prereleases are never published as updater assets. It does not connect to hosting. A failed release job leaves no usable new update metadata; inspect CI and correct the release before promoting it as latest. Assets are not overwritten by reruns. Do not move published version tags or replace assets; publish a new version instead. GitHub's latest stable release must point at a version with verified assets. Until the first such release, a 404 is harmless.

The package builder reads committed runtime files only, verifies fingerprints and archive contents, and keeps the exact stable ZIP root. It retains theme media, seasonal files, templates and patterns. It excludes repository history, tests, tooling, dependency trees and source maps. Actions' existing tested main artifacts remain available independently; those expire and are not update URLs. SHA256 manifests support release review; the updater trusts HTTPS and this GitHub repository, not a separate signing authority.

## One-time bootstrap and migration

This PR does not install anything. Existing installations cannot discover the updater until an administrator installs a release containing it. Back up the complete current theme and database first. Compare the live theme against the runtime ZIP, using `docs/live-theme-reconciliation.md`, `.github/deployment/live-snapshot-content.json`, the historical baseline and content-review records as starting evidence. Those records are historical and explicitly unreconciled, not a current backup. Preserve and reconcile live-only seasonal artwork, CSS, custom files and current editorial changes before proceeding. Commit required runtime files or move intentional site-specific customizations into a child theme/plugin or WordPress-managed media as appropriate. Do not install an unreconciled archive.

WordPress updates replace the **whole theme directory**, unlike the old incremental SFTP plan that preserved unknown files. Verify the installed directory is `tacobout.online-main` and test the replacement on staging, including menus, widgets, templates, media and seasonal behavior. Install the reconciled bootstrap ZIP through WordPress, or arrange an administrator-assisted file installation if upload/extraction limits prevent it. Keep a tested restore path. Subsequent higher published versions appear in Dashboard → Updates and are downloaded by the server when an administrator chooses Update.

Server fetching avoids browser upload limits but does not guarantee completion: outbound HTTPS, free disk space, filesystem permissions, PHP memory/execution limits, ZIP extraction and host quotas still apply. If extraction times out, ask hosting support to diagnose those limits or perform the one-time installation; this change does not alter hosting settings. Inactive themes may not load their own updater, so activate the bootstrap theme to discover releases.

References: [WordPress Update URI introduction](https://make.wordpress.org/core/2022/10/06/introducing-update-uri-theme-header-in-wordpress-6-1/), [native update hook](https://developer.wordpress.org/reference/hooks/update_themes_hostname/).

## Dotted directory names and the native installation route

The stable directory `tacobout.online-main` contains periods. WordPress's theme-card AJAX `wp_ajax_update_theme()` removes periods from its posted slug, turning it into `tacoboutonline-main`. Discovery correctly stores the update under the original directory. `Theme_Upgrader::bulk_upgrade()` sees no response for the altered directory and returns its “up to date” sentinel without selecting or downloading a package. The AJAX handler displays “The theme is at the latest version” even though the installed version is older. Refreshing discovery cannot repair this mismatch.

Use the existing native **Dashboard → Updates → Themes** checkbox for Tacobout Social, then **Update Themes**. That form goes through core's nonce/capability-protected `update-selected-themes` route, preserves the directory periods and selects the correct package. This is a native server-side theme update; no manual upload, custom installer or core patch is required. Do not rename the directory, alias the stripped slug into the update transient, or attempt theme-card Update Now again for this slug. The cache-refresh fix above addresses discovery only and does not fix WordPress's AJAX sanitizer.

`tests/native-theme-update-route.php` tests the real core sanitizer and `Theme_Upgrader` against checksum-pinned WordPress 6.8.3 sources. It reproduces the wrong-key “latest version” result and confirms the preserved slug selects the exact release package, stopping before any download, extraction or filesystem write. The same sanitizer remains in current WordPress development sources. Production request payload and update transient were not inspected; confirm the failed request used `action=update-theme` when diagnosing a particular installation.

Sources: [AJAX theme update handler](https://developer.wordpress.org/reference/functions/wp_ajax_update_theme/), [core theme upgrader](https://developer.wordpress.org/reference/classes/theme_upgrader/bulk_upgrade/), [native bulk route](https://github.com/WordPress/WordPress/blob/6.8.3/wp-admin/update.php).

### Verified production test: 3.8.29 → 3.8.30 (October 22, 2026)

The first theme-card **Update Now** attempt returned “The theme is at the latest version” and left the installed theme at 3.8.29. After that failure, the normal **Dashboard → Updates → select only Tacobout Social → Update Themes** flow successfully downloaded and installed the published 3.8.30 release. Signed-in theme details confirmed active version 3.8.30, and the live feed displayed the new reading-link chevron.

Post-update browser verification confirmed featured images, seasonal mascot, both enriched launch posts and their videos, the Facet 9/8c presentation and Trove cards remained healthy. No manual upload, SFTP, security-setting change or warning bypass was used. This completes the native server-side release discovery/download/installation test for 3.8.30. The discovery-cache correction in merged PR #364 is separate; its proposed 3.8.31 is not required to explain or repeat this successful bulk-form route and was not published by this test.
